# megamud.exe — what it does, as read from the binary

A working reference to MegaMUD 2.1's own logic (the Mudrev build in
`MegaMMUD v2.1 (Mudrev).zip`), read by disassembly so that mudengine can match
it exactly and, perhaps one day, host it as its engine. Every claim names the
address it was read at. What is still a reading rather than a certainty says so.

Started 2026-09-29. Add to it whenever the exe is opened.

- **Tools:** `docs/megamud/tools/mm.py` (`dis`, `str`, `field`, `fn`, `ini`). It
  reads the exe straight out of the zip in memory, so no copy of MegaMUD's
  binary is kept anywhere.
- **Settings map:** `docs/megamud/settings-map.txt` lists every INI key, its
  section and its slot in the session struct, generated by `mm.py ini 449aa0
  44d800` from the loader at `0x449aa0`.
- **Help:** `MegaMud.chm` in the same zip, which gives each setting's intent. The
  exe is what gives its exact behaviour, and the two disagree more often than
  you would hope.
- **Data files** (`Monsters.md`, `Items.md` and the rest, MDB2 format): see
  *Data files* at the end.

## How to read it

The program keeps one large session struct per connection, reached through
`esi`, `edi` or `ebx`, and almost every decision is a test of one of its fields.
The quickest way in is from a string (`mm.py str "Resting because"`) or a
setting (look its offset up in the settings map, then `mm.py field <offset>`).
Functions start with `55 8b ec` (`mm.py fn`).

The function reading `Name=value` INI integers is `0x4475d0`, and the one
reading strings is `0x4476f0`.

## Health: the rest decision (`0x414300`)

One long function, run whenever the script decides what to do next. It returns
1 as soon as it has sent something, so each pass does at most one of these
things, in this order:

1. **Full commands.** When mana is at or above `ManaFull%` of max and `e230` is
   clear, it casts `MaFullCmd`, logs "Casting %s because Mana/Kai is full", sets
   `e230` and returns (`0x4146aa`–`0x414759`). Mana below the line clears `e230`
   (`0x41475e`). The same happens for HP with `HpFull%`, `HpFullCmd`, `e22c` and
   "Casting %s because HP's are full" (`0x414768`–`0x41481c`). The latches start
   clear, so a character already full casts once when the script starts.
2. **Still needs resting** (a local, `[ebp-0x7c]`, at `0x414cb7`–`0x414d67`):
   true when a party member is being waited for, when mana is below `ManaFull%`,
   or when HP is below `HpFull%`.
3. **Flux, the mana regen** (`0x414d6e`–`0x414e10`). It casts `FluxCmd` when:
   - the tick monitor has asked for a recast (`e210`), or all of these hold:
     mana is more than 20 points below max, it is not mana-regenerating
     (`e20c`), and it is not meditating (`e1a8`);
   - and mana max is above 0, `FluxCmd` is set, and a tick has been measured
     (`d834` is not `-999`).

   A successful cast sets `e20c`, clears `e210` and returns. The 20 is a literal
   number of points, not a percentage.
4. **Conditions that make it rest:** can't move (held), blinded, diseased,
   confused, each logged as "Resting because we are …" and noted in
   `[ebp-0x70]` (`0x414e45`–`0x41501d`). A follower that needs rest while
   following says `@wait` ("Holding leader because we need to rest",
   `0x4150c2`).
5. **HP regen** (`0x41518a`–`0x415220`). It casts `RegenCmd` when:
   - a rest is happening, for a condition (`[ebp-0x70]`) or to full (`e2b0`);
   - HP is below max, not already HP-regenerating (`e208`), `RegenCmd` is set,
     and mana is above `ManaHeal%` of max.

   A successful cast sets `e208` and returns, so the rest itself goes on the
   next pass. Before the cast, `0x40cc80` equips the item the spell needs (see
   *Casting* below). When it sent something, the pass ends there.
6. Then the rest itself: "Resting because we are poisoned", and so on
   (`0x415255` on).

**The regenerating latches clear two ways.** One is the realm message that ends
the effect (the effect-end handler, `0x46bc78`, `0x46bc8c`). The other is the
30-second tick (`0x40a9c0`, the one logged `{30s}`): when HP is at max and mana
is at max (or the class has none), it clears every effect flag from `e1ec`
through `e20c`. So a regen spell whose realm prints no ending line is not recast
until the character has been completely full once.

## Health: the flux tick monitor (`0x494c90`)

It runs on each mana reading, and does nothing when `d838` is set, when no tick
has been timed yet, while meditating, with mana at max, or with HP below 1.

- `tick = mana − previous mana`. A gain is a tick. So is no gain for more than
  34 seconds (`0x22`, on the `_time64` clock) since the last one, which is recorded as a tick of 0.
- Each tick stamps `d828` and stores its size in `d834`.
- While mana regen is believed up (`e20c`), a negative tick, or a tick below
  `FluxMin` when `FluxMin` is above 0, sets `e210` (a recast); anything else
  clears it (`0x494d17`–`0x494d36`).

`d838` is set by the cast function (`0x40cb06`, inside `0x40c8a0`), by the
message handler (`0x46b8d2`), by `0x42a834` and by `0x465d90`/`0x47c280`. The
next reading after any of them only re-baselines (`0x494d43`). So a spell's
cost never reads as a slow tick.

## Rest and meditate: pre/post commands

Read for PR #37 on 2026-09-29.

- **Pre-rest** (`0x4140c0`) is sent just before `rest`, once per sit-down,
  when `PrePostRest` is on. It sets the owed flag `e1ac`, which only post-rest
  clears, so a heal cast between sit-downs never swaps the kit back.
- **Post-rest** (`0x413c50`) is sent just before the next action, never while HP
  is full. Its callers are a path step, a move, an attack, a hide or sneak, a
  trap disarm, an equip, and switching to meditation.
- **Pre-/post-meditate** follow the same pattern: `0x413e80` / `0x413b50`, owed
  flag `e1b0`, and `PrePostMeditate`.
- The message handler is `0x47a7e0`. It sets `e1a8` on "You are now meditating".

## Casting

- **The cast** is `0x40c8a0(session, spell, 0)`, which returns nonzero when it
  sent. It sets `d838`, so the flux monitor skips the mana it spends.
- **The item a spell needs** (`0x40cc80`, called before the HP regen and flux
  casts):
  - it looks the spell up (`0x4a2410`) and needs mana at or above the spell's
    cost (`+0x60`);
  - when the spell names an item (`+0x2a`) and that item is not worn
    (`0x4530c0` finds it, `+4 & 1` is "worn"), it first sends any owed
    post-rest or post-meditate command (`0x413c50`, `0x413b50`);
  - otherwise it sends `equip <item>`, logs "Equipping item %s for spell", and
    counts the swap (`+0xa5f8`, `+0xa5d9`).

  It returns 1 when it sent something (the caller waits a pass), 0 when
  nothing is needed, and -1 when the item is already worn. Whatever puts it
  back afterwards has not been read yet.

## Messages.md effects → state

A row's effect bits (row `+0x114`) set these flags on onset (`0x46aada`–`0x46ab64`) and clear them on the row's ending (`0x46bc1e` on):

| Bit | Effect (our name) | Flag |
|---|---|---|
| `0x01` | blind | `e1ec` |
| `0x02` | confused | `e1f0` |
| `0x04` | poisoned | `e1f4` (`e1f8` cleared too) |
| `0x08` | losing-hp | `e204` |
| `0x10` | held | `e214` |
| `0x20` | no-attack | (not yet read) |
| `0x40` | diseased | `e200` |
| `0x80` | hp-regen | `e208` |
| `0x200` | mana-regen | `e20c` |

`0x400` (anywhere), `0x800` (conversations), `0x4000` (chase) and `0x8000`
(disabled) are matching options, not effects. See `src/shared/messageTriggers.ts`.

## Party movement

Read for PR #35/#39, 2026-09-29.

- **`@party` path steps.** A path step whose command starts with `@party `
  (the check is a `strncmp` of 7 characters, at `0x409df8`, `0x40a0eb` and
  `0x40a3e1`) is handled like this when leading, with party size above 1:
  - the bare command goes to the pending list (`0x48ab60`), then `par`;
  - the `@party <command>` line itself goes straight to the socket
    (`0x42d9f0`), behind a prefix held at `+0x7d21`. MegaMUD puts the same
    prefix before `@kill` (`0x42bb2a`), and the help says `@kill` is said.

  So the say reaches the wire ahead of the move. Solo, only the bare command
  goes. The help: "@party … is usually embedded within path files to keep the
  party together in places where the party gets separated by the game."
- **The pending list** (`0x48ab80`). While scripting (`e164`), a command is
  queued rather than sent. More than 200 pending (`+0x2374`) logs "[Pending
  command overflow]".
- **Invite** (`0x408039`, "Inviting player %s"): sends either `invite %s` or
  the telepath `/%s @join`, chosen by a flag (`0x408050`), never both.
- **Per-player flags** (the Players dialog, `idh_dlg_plyrinfo`):
  - "Invite To Party If Seen": re-invite a member left behind, "then waits
    for the player to join and then continues on".
  - "Join Party If Invited".
  - "Chase Player If Seen": follow them when seen leaving.

  None of the three has been located in the exe yet.
- **Chase rows.** `Messages.md` rows flagged `0x4000` pair a departure
  sentence with the command that follows it (`{target} enters a manhole in the
  ground!` → `go manhole`). The string "Chasing" is at `0x54eab0`, used by
  `0x4ac36a`; how the exe gates them is not yet read.

## Data files (MDB2)

Decoded 2026-09-23 from the loaders: monsters at `0x46c690` and items at
`0x459860`. The dialogs are 324 and 316 in `MegaRes.dll`.

**The container** (all six `.md` binaries):
- An `MDB2` header page 0, then 1 KB pages.
- Each page has a 12-byte header: u16 level (0 = leaf), u16 record count,
  u32, u16, u16.
- Records run back to back, each as:
  - a u8 length (the span is length + 1);
  - a u8 type (1);
  - the key, a decimal id string ending in NUL;
  - the body: 4 zero bytes, `0x80`, then the struct the loader reads (`0xd3`
    = 211 bytes for monsters).
- Offsets below are from body + 5 ("B"). Leaf records are unique per key.

**Monsters (B):**
- `+0` u16 id; `+2` name[31].
- `+0x21` u32 flags `& 0x3fffffff`:
  - `0x08` find first; `0x100` don't backstab; `0x200` not hostile;
    `0x400` check if alive; `0x800` stop to kill;
  - the priority nibble `0xf0`: `0x80` first, `0x40` high, 0 normal, `0x20`
    low, `0x10` last.
- `+0x25` u8 relationship: 0 unknown, 2 friend, 3 avoid, 4 enemy, 5 flee,
  6 hang up.
- `+0x26` char[5] pre-attack spell; `+0x2b` char[5] attack spell;
  `+0x30`/`+0x32` i16 max casts.
- `+0x39` i16 max HP; experience is u16 `+0x37` (or u32 `+0x94`).
- The rest are close to realm stats: regen `+0x35`, MR `+0x3d`, follow%
  `+0x3f`, AC `+0x41`, DR `+0x43`.

**Items (B):**
- `+0` u16 id; `+2` name[31]; `+0x20` shop[41]; `+0x49` "if needed"
  path[14] (e.g. `SLMBLOOP.mp`).
- `+0x57`/`+0x59` i16 min/max; `+0x5b` u8 type; `+0x5d` i16 weight;
  `+0x5f` u32 price; `+0xa3` u8 body location.
- `+0x63` u32 flags `& 0x38ffffff`: `0x2` collect, `0x4` buy, `0x8`
  sell/stash, `0x10` equip, `0x20` find, `0x40` cannot take, `0x200`
  backstab, `0x400` must have min, `0x800` discard, `0x1000` open, `0x20000`
  loyal. Loyal is also set when any of the ten u16 at `+0x79` equals 100.

The relationship value table is at `0x562410` (lookup `0x4462e0`, id 10). Our
readers are in `src/shared/megamudDb.ts`.
